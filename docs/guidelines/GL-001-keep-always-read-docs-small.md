# GL-001 作業のたびに読む文書を小さく保つ

## ルール

作業の開始時に読む文書（入口、README、索引）には、そのときの作業に必要な情報だけを置く。
変更履歴、経緯、過去の議論は別のファイルに分け、常に読む文書からは1行のリンクだけを置く。分けたファイルは、経緯をさかのぼるときだけ読む。

## 理由

常に読む文書に履歴が積み重なると、読むたびの負担（AI ではトークン）が増え、必要な情報が埋もれる。履歴は将来の振り返りに要るが、毎回の作業には要らない。

## 適用条件

作業の開始時に読むよう指定されている文書（AGENTS.md §1 の文書と、各索引）に記述を足すとき。

## 例外

- 現在の状態（タスクの状態など）は履歴ではない。状態を書く場所は1か所にする（OVERVIEW.md §5 教訓10）。
- 作業のたびに必要な判断の基準は、常に読む文書に置いてよい。

## 例

REV-002-F01: docs/README.md §5 にあった開発基盤の版の表を [history.md](../history.md) に移し、README にはリンクだけを残した（TASK-001）。

## 確認方法

- 確認: レビューで、常に読む文書に、変更履歴・経緯・過去の議論が足されていないかを見る。
- 自動検証: なし（記述が履歴かどうかを、機械的に判定できない）。
